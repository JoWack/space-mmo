# ADR-0013 — Terrain stays a function; everything else gets collision primitives

**Status:** Accepted · 2026-08-27 · extends [ADR-0002](0002-generation.md), and narrows the
reach of the reasoning in [ADR-0011](0011-caves-are-authored-volumes.md)

## Context

Nothing in this game is solid except the ground, and the ground is solid because it is a
function rather than a mesh. `FPlanetTerrain::ResolveContact` says so itself:

> This, not the mesh, is what collision means here. The dedicated server has no mesh to
> collide against and must still agree about where a player may stand, so contact has to
> be a function of position — the same function the client tessellates. Colliding against
> generated triangles would give the server and the client two different surfaces and no
> way to notice they had diverged.

Everything else is deliberately intangible. Every component in the project calls
`SetCollisionEnabled(NoCollision)` — the planet, the ship, the stations, the deposits, the
character, even the editor preview markers — and there is not one line trace, sweep or
overlap query anywhere in `client/Source`. Chaos has never run in this project.

That was fine while the only thing to stand on was a height field. It stopped being fine
when a station became a building somebody wants to walk into, and it never covered running
straight through a parked ship.

Four things constrain the choice. Three were read out of the code; the fourth is about how
the game is actually being made.

**Client-side collision cannot work here.** `ASpaceMMOCharacterPawn::ReconcileWithServer`
pulls the client's position toward the server's on every net update. A client that stops at
a wall the server does not know about is dragged through it by the next correction. Whatever
answers "is there a wall" must answer identically on both machines.

**A height field cannot express a building.** It answers one radius per direction, and a
building has several surfaces along the same ray: outside ground, floor, ceiling, roof. This
is the expressiveness problem ADR-0011 identified for caves, and no tolerance tuning reaches
it.

**Analytic volumes are already the idiom.** `ASpaceMMOShipPawn` passes
`HullRadiusKilometres = 0.002` to `ResolveContact`; a ship is already a two-metre sphere as
far as contact is concerned.

**Assets arrive by two routes and both must work.** A-02 is generated by
`tools/greybox/a02_capital_hub.py` from the numbers on a plan sheet. Other buildings will be
assembled in Blueprints from bought kits. A decision that gives interiors only to programs
is a decision about how art may be made, and that is not a trade worth taking to protect a
property.

## Decision

**Terrain remains a pure function of position. Everything else is solid the ordinary Unreal
way: simple collision primitives on the asset, queried by both machines.**

1. **`FPlanetTerrain::ResolveContact` does not change.** The dedicated server has no terrain
   mesh and will not grow one. Ground contact stays a function both machines evaluate, which
   is ADR-0002 and is not in question.

2. **Stations, ships and deposits carry ordinary collision.** Simple primitives — boxes,
   capsules, convex hulls — on the static mesh, not the render triangles. From the greybox
   script that means emitting `UCX_<MeshName>_01` meshes into the same FBX, which UE imports
   as that mesh's collision automatically; the walls are already boxes, so this is nearly
   free. From a bought kit it means whatever collision the vendor shipped, plus primitives
   added in the mesh editor for anything missing.

3. **Queries, never simulation.** Pawns stay kinematic and own no physics body. Movement
   sweeps a capsule shape against the world and resolves the hit itself, exactly as it
   already resolves against the terrain. Chaos is used as a spatial query service and
   nothing else, so there is no accumulated physics state for the render-origin rebasing of
   ADR-0001 to disturb.

4. **The seam stays where it already is.** `ASpaceMMOCharacterPawn::ResolveSurface` already
   consults the world, iterating planets and producing `SurfaceNormal` and `bOnGround` for
   the walk model. The sweep goes there. `FCharacterWalkModel` keeps its signature, keeps
   knowing nothing about actors, and keeps being tested by walking a full arc around a
   planet with no world loaded.

5. **The server runs the same queries.** It already spawns stations and deposits; it will
   carry their collision primitives, which are small. Agreement comes from both machines
   holding the same asset and asking the same question, not from the answer being a pure
   function.

## Consequences

Positive:

- **Both asset pipelines get interiors.** A generated building and a kit-assembled one are
  solid by the same mechanism, and how a building is made stops being a decision about
  whether players can walk into it.
- **It is the standard approach**, so the tooling exists, the failure modes are documented,
  and knowledge about it transfers in and out of this project.
- **The movement maths stays pure.** The one thing worth protecting — a model the server
  integrates, the client predicts with, and a test drives with no world at all — is
  untouched, because the world lookup lives in the pawn where it already lived.
- **Nothing is transmitted.** Both machines derive solidity from the same shipped asset,
  which is the property ADR-0002 protects, kept.

Negative, and accepted:

- **Chaos now runs.** A system with its own failure modes enters a project that had none,
  and "no physics anywhere" stops being a true and simplifying statement about this
  codebase.
- **The dedicated server carries collision geometry.** Cheap for primitives, but it is no
  longer true that the server holds no geometry at all, and somebody will eventually have to
  watch that number.
- **Two mechanisms decide solidity**, and the boundary between them is where bugs will live:
  a station's floor is a collision primitive while the ground under it is a function, and
  the two meeting badly at a threshold is the first thing to go wrong.
- **Collision has to be verified per asset.** A mesh imported without it is silently
  intangible, which looks exactly like a bug in the movement code — and this project has
  already lost time to imports whose options were wrong in ways nothing reported.
- **Determinism depends on both machines holding identical assets.** A divergence is silent
  rather than loud, in a way a shared pure function could not be.

## Alternatives considered

**Generate a collision description alongside the mesh and evaluate it as a pure function.**
The first draft of this ADR. Every station's script would emit boxes and planes into a
description both machines read, keeping contact a pure function of position for buildings
exactly as it is for ground.

Rejected, and the reasoning is recorded because it is the mistake a future reader is most
likely to repeat. It gives interiors only to buildings that are generated by a program, so a
station assembled from a bought kit stays scenery — a real constraint on how art may be made,
imposed to protect a property that turns out not to need protecting. Agreement between server
and client comes from both holding the same data and asking the same question; being a *pure
function* is one way to achieve that and not the only one, and a shipped asset both machines
load is another.

The argument that finally failed was the strongest-sounding one: that world-space physics
collides with ADR-0001's render-origin rebasing. That was borrowed from ADR-0011's rejection
of a voxel plugin, which does its own world management and streaming. A stateless shape sweep
in the current frame is not that — rebasing shifts everything coherently between frames, and a
query made after transforms are applied sees one consistent world. The objection applies to
simulated bodies carrying accumulated state, and this decision has none.

**Authored collision volumes in `data/`.** ADR-0011's cave answer applied to buildings:
hand-authored boxes per station, seeded and served. Rejected because it puts geometry through
the C# API for no benefit — the client already knows which station it is looking at — and
because it reintroduces the seam ADR-0011 named as where its bugs would live, with a
hand-authored volume and a separately-authored mesh kept agreeing at every doorway only by
somebody remembering to.

**Client-side collision only.** Rejected as unworkable rather than undesirable: the
reconciliation in `ReconcileWithServer` would drag a player through any wall the server did
not know about. It is not a question of trusting the client; the architecture actively
defeats it.

**Full physics simulation.** Never wanted. Nothing here needs bodies, constraints or
integration — the walk model already decides how a character moves, and it needs one question
answered: is something in the way. Simulation would also put the render-origin objection back
on the table.
